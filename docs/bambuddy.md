# Bambuddy for the A1 mini

Optional independent project `ohara-bambuddy`, using the official release
`1.2.5.7` pinned by multi-architecture digest in `versions.bambuddy.env`.
The existing main stack and optional projects remain independent.

## Storage and deployment

The owner selected internal storage on this host. On a new target, confirm the
owner's choice before preparing the instance. The default is `DATA_ROOT/bambuddy` (`/ohara/bambuddy` on this host), on the internal
ext4 SSD. `data/` contains SQLite, archives and application-managed keys;
`logs/` is separate. It is not part of the media/Immich library or mergerfs pool.
No media data is copied or migrated. Overrides belong in the private `.env`:

```dotenv
# Defaults shown; confirm real storage first.
BAMBUDDY_ROOT=/ohara/bambuddy
BAMBUDDY_MOUNT=/
```

The helper rejects symlinks, overlapping application/media paths, wrong mounts
and unsupported/network/FUSE filesystems. Existing ownership and files are
preserved; non-root UID/GID match Ohara. Missing bind paths are never automatically
created by Docker. If selecting external storage, review mount-dependent boot
ordering before activation; this default deployment assumes internal storage.

```sh
scripts/bambuddy check --static
scripts/bambuddy prepare
scripts/bambuddy up
scripts/bambuddy status
```

`up` validates storage and starts only this project. The container runs non-root
with no-new-privileges, all capabilities dropped except the official Python
binary's NET_BIND_SERVICE bounding requirement. No device, Docker/Tailscale
socket or unrelated host files are mounted. State is private (mode 0700). No
password, API key or JWT secret is generated by the helper; the application
creates its own internal keys, which must stay with persistent state.

## LAN HTTPS, Homepage and DNS

Backend: `127.0.0.1:8008` to container port 8000. The reviewed host baseline adds
`https://bambuddy.xdadwal.in` with the existing wildcard certificate, source checks
on both HTTP and HTTPS, WebSockets, unbuffered responses, 24-hour stream timeouts
and 1 GiB proxy body limit. This remains LAN-only even after owner onboarding.
It does not add public DNS, a router port forward or shared authentication.

After reviewing the candidate and confirming the current host/certificate:

```sh
sudo scripts/lan-proxy --apply
scripts/bambuddy homepage
scripts/bambuddy dns
```

The privileged command backs up the current managed LAN file, tests/reloads Nginx
and rolls back on error. Other routes are preserved. Homepage adds a plain Utility
card without forwarding credentials. DNS adds only the exact Bambuddy rewrite to
the verified AdGuard LAN IPv4, preserving other records and rejecting conflicts.
Fresh seeds contain both integrations. Do not modify router/client DNS.

## Owner setup and printer connection

1. Open https://bambuddy.xdadwal.in from an allowed LAN client. Enable native
   authentication and create the owner in the first-run UI. Do not leave auth off
   merely because the route is LAN-only. Do not send the chosen password in chat.
2. Choose the printer operating mode deliberately. Full local control requires
   LAN-only/Developer Mode and changes Bambu cloud availability. Standard LAN
   operation without Developer Mode is limited by firmware; read-only monitoring
   must be verified rather than promising full cloud and local control together.
3. Add the **A1 mini** manually by its real reserved LAN IP, serial number and
   access code, entered privately in Bambuddy's UI. Do not assume example values.
   Reserve its address on the router deliberately; setup does not alter DHCP.
4. Verify a read-only printer connection/status and camera where the A1 mini and
   firmware support it. Bridge networking intentionally omits SSDP discovery; no
   virtual-printer/proxy listeners or server-side slicer sidecars are enabled. The
   connection diagnostic automatically warns about bridge mode; this does not
   mean an established manual-IP connection is broken. Host mode is not needed
   merely to clear that warning.
5. Before relying on archiving, verify the printer has a microSD card and confirm
   the current upstream file-on-card workflow for A1-family prints. Missing
   printer-side files can leave thumbnails/filament metadata unavailable. Owner
   printing, heater/motion controls, queues and automation are separate actions;
   deployment does not exercise them.

Use the supported UI to preserve accounts and encrypted printer configuration.
Do not reset the database to repair connection problems. A healthy container or
`requires_setup=false` does not prove owner login or printer communication.

## Checks, backups and recovery

```sh
scripts/bambuddy check
scripts/bambuddy status
python3 tests/smoke_bambuddy.py
scripts/bambuddy stop
```

The disposable smoke uses no production credentials, creates no printer/account
or print job, and checks non-root readiness plus state persistence after
recreation. `tests/smoke_lan_proxy.py` separately checks source restrictions and
routes using fixture certificates/backends. Trusted live HTTPS, DNS over UDP/TCP,
owner login and actual printer status are separate acceptance checks.

Stop Bambuddy before a filesystem copy of its entire `data/` (including SQLite,
internal keys, archives and backups) and `logs/`, or use its supported in-app backup
workflow after owner setup. A local backup is not an independent backup or a
proven restore. No external backup destination/restore test is implemented here.
Retiring the service must preserve its data: stop it, remove only its managed
proxy/card/rewrite deliberately, and never use volume/data deletion for rollback.
